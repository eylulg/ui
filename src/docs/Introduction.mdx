# @eylulg/ui

The component library behind all of Eylül's projects: React 19 components on React Aria
Components, Tailwind CSS 4 design tokens, nine theme variants and the shared page chrome.
React Aria provides behaviour, focus management and ARIA. The tokens provide every visual decision.

Use the **Theme** toolbar to switch between light and dark, and the **Variant** toolbar to see any
story in a project's colour. The **Theme variants** pages show every component in each project's
theme, in light and dark. **Chrome** has the top nav, sidebar, project switcher, theme toggle,
footer and logo.

## The design language

- **Frame.** Warm sand paper in light mode, warm brown in dark. It is the same in every project.
- **Colour is the project.** Each project has one seed colour. Green is the portfolio's and the
  logo's.
- **Contrast.** Text passes WCAG AA in both modes and non-text marks reach 3:1.
  `npm run contrast` checks every variant.
- **Voice.** Project names are Title Case, everything else is sentence case.


## Usage

Import the stylesheet and one theme variant once at the root of the app, then import components
from the index or from a per component entry point. An app that runs Tailwind 4 imports
`@eylulg/ui/theme.css` into its own Tailwind entry instead of `styles.css`.

```tsx
import '@eylulg/ui/styles.css';
import '@eylulg/ui/themes/portfolio.css';
import { Button } from '@eylulg/ui/button';
import { Input } from '@eylulg/ui/input';

export function SignIn() {
  return (
    <form className='flex flex-col gap-4'>
      <Input label='Email' type='email' isRequired />
      <Button type='submit'>Sign in</Button>
    </form>
  );
}
```

Dark mode is class based: `ThemeToggle` writes `dark-mode` on `<html>`. `dark` works too, on
`<html>` or any ancestor.

## Theme variants

A variant changes colour only. Fonts (Manrope for headings, Inter for text, JetBrains Mono for code
only), text size, density and shape are the same in every theme.

| Variant          | Project               | Colour     |
| ---------------- | --------------------- | ---------- |
| `portfolio`      | Portfolio             | Green      |
| `workspace`      | Workspace             | Slate blue |
| `review`         | Review Companion      | Eucalyptus |
| `control-room`   | Agent Workflows       | Clay       |
| `watchlist`      | Watchlist             | Rose       |
| `tokens`         | Tokens to Tailwind    | Iris       |
| `plain-language` | Plain Language Add-in | Sea glass  |
| `sudoku`         | Sudoku                | Ink        |
| `assistant`      | Assistant Studio      | Plum       |

In light mode the seed is the solid fill and carries white text. In dark mode a lighter seed is
the solid and carries the page colour as text. The brand scale is generated from the seed in oklch
with the same lightness at each step, so contrast matches across variants.

To switch variants at runtime, import `@eylulg/ui/themes/all.css` and set `data-ui-variant` on
`<html>` or on any container.

## How the tokens are layered

1. **Primitive scales** (`--color-brand-*`, `--color-gray-*` and so on) live in `@theme` and
   generate Tailwind utilities such as `bg-brand-600`.
2. **Semantic tokens** (`--ui-text-*`, `--ui-bg-*`, `--ui-border-*`, `--ui-fg-*`) point at the
   primitives and are redefined under `.dark` and `.dark-mode`. Components only use this layer,
   through utilities like `text-primary`, `bg-elevated` or `border-default`.
3. **Density and text size** (`--density-*`, `--text-*`) size controls, rows, cells, cards and
   type through utilities like `h-control-md`, `py-item-y`, `p-card` and `text-md`.

## Spacing

Spacing has one base, `--spacing: 0.25rem`, so `p-2` is 8px and `gap-6` is 24px.

## Overriding the brand

Set your own seeds after the library stylesheet. Solid fills, tints, brand text and the focus ring
follow them.

```css
@import '@eylulg/ui/styles.css';

:root {
  --color-brand-seed: #3f6fb6;
  --color-brand-seed-dark: #8cb2eb;
}
```

The light seed needs 4.5:1 against white, because solid buttons put white text on it. The dark seed
needs 4.5:1 against the dark page. Run `npm run contrast` after adding a variant to `variants.ts`.

## Accessibility

- Keyboard support and ARIA patterns come from React Aria. Unit tests cover what this library adds,
  including where focus lands when overlays open and close.
- Every component has an axe test in both themes, and the **Accessibility** panel in this
  Storybook runs the same checks, colour contrast included, on every story.
- Focus rings show for keyboard users only, through `data-focus-visible`.
